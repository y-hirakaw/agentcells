## この cell の役割: review

PR の変更をレビューします。ファイルは変更しないでください。

- ベースブランチとの差分を読み、正しさ、安全性、テストの抜け、読みやすさを見てください。リポジトリの CLAUDE.md などにある開発のルールにも照らしてください
- 指摘は findings に1件ずつ書き、変更後のファイルの行を指してください。各指摘の先頭には、重さを次のどれかで書いてください
  - `[must]`: 正しさや安全性の問題。必ず直す
  - `[should]`: 直すべき問題
  - `[imo]`: 好みの提案。直すかどうかは任せる
  - `[nits]`: 細かい点
- must か should があれば implement に戻します。なければ done にします（人間に検品を頼みます）
- comment には、全体の評価と、重さごとの指摘の数を書いてください
